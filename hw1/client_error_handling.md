## 錯誤處理

### 1. REGISTER（註冊）

#### 輸入驗證
- **錯誤訊息**：`名稱不可為空。`
- **觸發條件**：使用者輸入空字串或只有空白字元
- **處理方式**：使用 `trim()` 函數去除前後空白，檢查是否為空

#### 傳送失敗
- **錯誤訊息**：`傳送失敗。`
- **觸發條件**：無法將註冊請求傳送至伺服器
- **處理方式**：終止程式

---

### 2. LOGIN（登入）

#### 輸入驗證

**使用者名稱驗證**
- **錯誤訊息**：`名稱不可為空。`
- **觸發條件**：使用者輸入空字串或只有空白字元
- **處理方式**：使用 `trim()` 函數處理後檢查

**帳號存在性檢查**
- **錯誤訊息**：`登入失敗：該帳號尚未註冊。`
- **觸發條件**：使用 `usr#0` 探測帳號時收到 `220 AUTH_FAIL` 回應
- **處理方式**：顯示錯誤訊息，回到選單

**Port 驗證**
- **錯誤訊息**：`Port 必須是數字。`
- **觸發條件**：輸入無法轉換為數字
- **處理方式**：清除輸入緩衝區，顯示錯誤，回到選單

- **錯誤訊息**：`Port 超出範圍。`
- **觸發條件**：Port 不在 1024~65535 範圍內
- **處理方式**：顯示錯誤訊息，回到選單

**登入驗證錯誤**
- **錯誤訊息**：`登入失敗：驗證錯誤。`
- **觸發條件**：正式登入時收到 `220 AUTH_FAIL` 回應
- **處理方式**：顯示錯誤訊息，回到選單

#### 傳送失敗
- **錯誤訊息**：`傳送失敗。`
- **觸發條件**：無法將登入請求傳送至伺服器
- **處理方式**：終止程式

#### 成功訊息
- **成功訊息**：`已登入，監聽埠 [port] 已啟動。`
- **觸發條件**：登入成功並啟動 P2P 監聽埠

---

### 3. LIST（查詢列表）

#### 權限檢查
- **錯誤訊息**：`Please login first`
- **觸發條件**：未登入狀態下嘗試查詢列表
- **處理方式**：顯示錯誤訊息，回到選單

#### 傳送失敗
- **錯誤訊息**：`傳送失敗。`
- **觸發條件**：無法將 List 請求傳送至伺服器
- **處理方式**：終止程式

---

### 4. TRANSFER（轉帳）

#### 權限檢查
- **錯誤訊息**：`Please login first`
- **觸發條件**：未登入狀態下嘗試轉帳
- **處理方式**：顯示錯誤訊息，回到選單

#### 輸入格式驗證
- **錯誤訊息**：`格式錯誤，例：AA#1000#BB`
- **觸發條件**：輸入格式不符合 `A#amount#B` 格式（缺少 `#` 分隔符）
- **處理方式**：顯示錯誤訊息，回到選單

#### 轉帳者驗證
- **錯誤訊息**：`Sender 必須是目前登入的使用者。`
- **觸發條件**：轉帳者名稱與目前登入使用者不符
- **處理方式**：顯示錯誤訊息，回到選單

#### 金額驗證
- **錯誤訊息**：`金額必須大於 0。`
- **觸發條件**：轉帳金額小於或等於 0
- **處理方式**：顯示錯誤訊息，回到選單

- **錯誤訊息**：`金額必須是數字。`
- **觸發條件**：金額無法轉換為數字（`stod()` 拋出異常）
- **處理方式**：顯示錯誤訊息，回到選單

#### 收款人驗證
- **錯誤訊息**：`找不到收款人或對方不在線上。`
- **觸發條件**：在線上使用者列表中找不到收款人
- **處理方式**：顯示錯誤訊息，回到選單

#### Port 解析錯誤
- **錯誤訊息**：`收款人 port 非法：[port]`
- **觸發條件**：收款人的 port 無法轉換為數字
- **處理方式**：顯示錯誤訊息，回到選單

#### P2P 連接失敗
- **錯誤訊息**：`無法連接到收款人 [receiver] ([ip]:[port])`
- **觸發條件**：無法建立與收款人的 P2P 連線
- **處理方式**：顯示錯誤訊息，回到選單

#### 傳送失敗
- **錯誤訊息**：`傳送失敗。`
- **觸發條件**：無法將轉帳訊息傳送至收款人
- **處理方式**：關閉連線，顯示錯誤，回到選單

#### 轉帳結果
- **成功訊息**：`Transfer OK!`
- **觸發條件**：收到 `Transfer OK` 回應

- **失敗訊息**：`Transfer Failed!`
- **觸發條件**：收到 `Transfer Failed` 回應或無法接收回應

---

### 5. EXIT（離開）

#### 傳送失敗
- **處理方式**：即使傳送失敗也會顯示 `Bye` 並離開程式

#### 成功訊息
- **成功訊息**：`Bye`

## 輸入驗證

### 字串處理
- 使用 `trim()` 函數去除輸入字串前後的空白字元（` \t\r\n`）
- 檢查處理後的長度是否為 0

### 數字驗證
- **Port**：使用 `cin >> p` 檢查是否為數字，範圍 1024~65535
- **金額**：使用 `stod()` 轉換並檢查是否大於 0，使用 try-catch 處理異常

### 格式驗證
- **轉帳格式**：檢查是否包含兩個 `#` 分隔符
- **使用者名稱**：檢查是否為空

## 網路錯誤處理

### Socket 操作
- **socket() 失敗**：顯示 `socket() failed`，程式終止
- **connect() 失敗**：顯示 `connect() failed`，程式終止

### 伺服器通訊
- 使用 `talk_to_server()` 函數統一處理伺服器通訊
- 檢查 `send_all()` 和 `recv_once()` 的返回值
- 傳送失敗時終止程式

### P2P 通訊
- **連接失敗**：顯示錯誤訊息，回到選單
- **傳送失敗**：關閉連線，顯示錯誤，回到選單
- **接收失敗**：判斷為轉帳失敗

### 超時處理
- P2P 連接使用 2 秒超時（`SO_SNDTIMEO`）
- 連接失敗時會嘗試 fallback 到 localhost（127.0.0.1）

## 使用者體驗設計

### 提示訊息
- 所有錯誤訊息都使用中文，清楚明確
- 成功訊息也會明確顯示
- 操作流程有明確的提示（如：`輸入註冊名稱:`、`輸入使用者名稱:`）

### 錯誤恢復
- 大部分錯誤都會回到選單，讓使用者可以重新操作
- 只有嚴重的網路錯誤才會終止程式

### 自動操作
- 轉帳前後自動更新列表
- 登入成功後自動啟動 P2P 監聽埠
- 轉帳後自動刷新列表確認結果

## 程式碼結構

### 錯誤處理函數
- `trim()`：字串處理
- `send_all()`：確保完整傳送
- `recv_once()`：接收完整回應
- `talk_to_server()`：統一的伺服器通訊介面

### 狀態管理
- `logged_in`：追蹤登入狀態
- `login_user`：目前登入的使用者名稱
- `listen_port`：P2P 監聽埠
- `listener_started`：確保監聽只啟動一次

### 執行緒安全
- 使用 `mutex`（`io_mtx`）保護伺服器通訊和輸出操作
- P2P 監聽使用獨立執行緒處理

## 總結

`client.cpp` 實現了完整的錯誤處理機制，包括：
1. **輸入驗證**：檢查所有使用者輸入的格式和範圍
2. **權限檢查**：確保操作在正確的狀態下執行
3. **網路錯誤處理**：處理各種網路連線和通訊錯誤
4. **使用者友善**：提供清晰的中文錯誤訊息和操作提示
5. **錯誤恢復**：大部分錯誤允許使用者重新操作，不會直接終止程式

這些設計確保了程式的穩定性和使用者體驗。
